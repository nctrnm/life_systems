# Full Loop Example

This example shows how Life Systems can move a recurring everyday issue through the full decision architecture.

## 1. Problem Diagnosis

**Problem Statement:** A person keeps delaying an important application because the task feels too large and unclear.

**Trigger:** The application requires multiple materials and the person has not broken the work into smaller parts.

**Context:** The person has limited time, competing responsibilities, and no written sequence for completing the application.

**Conflict:** The desire to submit the application conflicts with the lack of a clear execution path.

**Impact:** Delay reduces opportunity access and increases stress.

## 2. Complexity Mapping

**Domain:** Complicated

The task is not chaotic or unknowable. It requires analysis, sequencing, and document preparation.

**Response:** Sense → Analyze → Respond

## 3. Decision

**Alternatives:**

1. Complete the application all at once.
   **Pros:** Fast if successful.
   **Cons:** High friction and high avoidance risk.

2. Break the application into a three-day sprint.
   **Pros:** More realistic, easier to begin, and better suited to limited bandwidth.
   **Cons:** Requires tracking and follow-through.

3. Delay until motivation improves.
   **Pros:** Lower immediate pressure.
   **Cons:** Opportunity risk increases.

**Recommendation:** Choose Alternative 2 because it lowers friction while preserving the opportunity.

## 4. Execution

**Step 1:** Day 1, gather requirements and list missing materials.

**Step 2:** Day 2, draft the main response or document.

**Step 3:** Day 3, review, revise, and submit.

## 5. Audit

**Original Trigger:** The task felt too large because it had not been broken into parts.

**Trigger Neutralized:** Yes, if the task was converted into steps and submitted.

**New Context:** The person now has a reusable application sprint model.

**Emergent Friction:** Future applications may still require earlier deadline tracking.
