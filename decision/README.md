# Decision Analysis

The Decision module turns diagnosis into a defended choice.

After a problem is defined and the situation is mapped, the user needs a clear way to compare possible responses. This module provides a structured decision document that separates analysis, alternatives, recommendation, implementation, and conclusion.

## Document Architecture

### 1. Problem Statement

A short statement of the central issue.

### 2. Analysis

The longest section of the decision document. It explains why the problem matters and what facts, constraints, warrants, and impacts shape the decision.

### 3. Alternatives

A set of possible paths forward. Each alternative should include what the option involves, its pros, and its cons.

### 4. Recommendation

The selected path. The recommendation should follow logically from the analysis and alternatives.

### 5. Implementation

The concrete next steps needed to begin the selected path.

### 6. Conclusion

A brief summary of the expected resolution.

## Purpose

This module prevents vague decision-making. It helps users move from pressure or preference into a clear, documented choice.
